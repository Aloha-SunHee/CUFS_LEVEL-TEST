# CUFS 중국어학부 레벨테스트 웹앱

학번과 이름으로 접속해 100문항(듣기 50 + 읽기 50)과 공통 문항 12개(두 번째 시험부터는 재확인 문항 10개 추가)를 풀고, 난이도별 정답률로 수준을 진단받는 웹앱입니다. 처음 접속하면 시험 1개(1회)만 보이고, 한 번 응시한 뒤에는 **지난 시험 다시보기 / 새로운 시험 도전** 두 탭이 나옵니다. 새로 도전하면 아직 보지 않은 다음 회차(2회, 3회…)가 출제되고, 결과는 지난 시험과 비교해 보여 줍니다.

## 진단 방식
config.js의 `DIAGNOSIS_TIERS`에서 위에서부터 차례로 보고, 조건(난이도별 정답률)을 모두 만족하는 첫 등급으로 진단합니다.

| 등급 | 조건 |
|---|---|
| 5단계 (HSK 5~6) | 고급 60% 이상 + 중급 75% 이상 |
| 4단계 (HSK 4~5) | 고급 35% 이상 + 중급 65% 이상 |
| 3단계 (HSK 3~4) | 중급 45% 이상 + 초급 70% 이상 |
| 2단계 (HSK 1~2) | 초급 45% 이상 + 입문 60% 이상 |
| 1단계 (입문) | 그 외 |

진단 결과 아래에는 **추천 과목**이 함께 나옵니다. 과목 목록은 config.js의 `COURSES`에서 고치면 됩니다.
- 1·2단계: 초급 과목(중국어입문, 한자쓰기와 워드연습 등 7개)
- 3단계: 중급 과목(중국어 문법·작문Ⅰ/Ⅱ, 중급중국어회화 등 12개)
- 4단계: 중급 과목 + '다음 단계로 도전해 볼 과목'으로 고급 과목
- 5단계: 고급 과목(중국어로 읽는 중국문화, 취업인터뷰중국어 등 9개)

## 공통 문항 · 재확인 문항 · 난이도별 비교 (2026-11 추가)
회차마다 문항이 달라서 생기는 두 가지 문제(같은 문항 재오답을 알 수 없음, 총점 비교가 부정확함)를 보완합니다.

- **공통 문항** (`data/anchor.js`): 모든 회차에 똑같이 나오는 12문항(입문·초급·중급·고급 각 3, 읽기). 시험 화면의 ‘공통 문항’ 탭에 나오고, 결과에서 지난 시험과 **같은 문제로** 비교합니다(예: 5/12 → 11/12). 시간 8분 추가.
- **재확인 문항**: 두 번째 시험(학기말 등)부터, 가장 최근 다른 회차 시험에서 틀린 문항 중 `RECHECK_COUNT`개(기본 10, `config.js`)를 난이도별로 고르게 골라 ‘재확인 문항’ 탭에 다시 냅니다. 아직 해결 못 한 문항을 먼저 고릅니다. 결과에서 🔴 또 틀린 문제 / 🟢 이번엔 맞힌 문제로 보여 주고, 또 틀린 문항은 오답노트의 반복 오답에 쌓입니다. 문항당 1분 추가.
- 공통·재확인 문항은 **수준 진단 점수(100문항)에는 넣지 않습니다.** 진단 기준이 그대로 유지됩니다.
- **난이도별 비교**: 지난 시험과의 비교, 학생 홈의 성취도 추이, 교수자 대시보드 모두 총점 대신 **난이도별 정답률**(입문·초급·중급·고급)과 그 평균, 공통 문항으로 비교합니다. 예전 기록처럼 난이도 정보가 없으면 총점으로 대신합니다.
- ‘오답만 다시 풀기’ 결과에서 지난 시험 점수와 %p를 비교하던 문제(문항 수가 달라 의미 없는 값)를 고쳤습니다. 이제 극복·반복 오답 수만 보여 줍니다.
- 기록: 재확인 문항은 문항기록 시트에 **원래 세트·문항 번호**로, 모드 `recheck`로 저장됩니다. 공통 문항은 세트 `anchor`로 저장됩니다. 제출기록 시트에 `입문·초급·중급·고급·공통문항·재확인(또틀림/문항)` 열이 추가됩니다.
- **이미 운영 중인 시트는** Apps Script에 새 `Code.gs`를 붙여 넣고 `setup`을 한 번 더 실행(머리글 갱신)한 뒤, 배포 → 배포 관리 → 새 버전으로 다시 배포하세요.

## 듣기 음성을 원어민 녹음으로 바꾸기
1. `recording/듣기_원어민_녹음대본.xlsx`의 ‘녹음목록’ 시트 한 줄 = 녹음 파일 1개입니다(360개). ‘녹음 대본’을 읽어 녹음하고 ‘파일명’으로 저장합니다.
2. GitHub에서 `audio/lt1` ~ `audio/lt8` 폴더를 열고 **Add file → Upload files**로 올립니다. 같은 이름의 AI 음성(mp3)은 자동으로 바뀝니다.
3. m4a·wav 등으로 올려도 `.github/workflows/convert-audio.yml`이 1~2분 안에 같은 이름의 mp3로 바꾸고, 소리 크기를 맞추고, 앞뒤 무음을 줄입니다(Actions 탭에서 확인).
4. 녹음하지 않은 파일은 AI 음성이 그대로 남습니다. 원어민 녹음으로 바꾼 뒤에는 `make_audio.py`로 음성을 다시 만들지 마세요(사람 녹음을 덮어씁니다).

## 설치
1. 이 폴더 전체를 GitHub 새 저장소에 올리고, Settings → Pages에서 main 브랜치를 켭니다.
2. 새 구글시트에서 확장 프로그램 → Apps Script를 열고, `apps-script/Code.gs`를 붙여 넣은 뒤 `setup`을 한 번 실행합니다.
3. 프로젝트 설정 → 스크립트 속성에 다음을 넣습니다.
   - `TEACHER_PIN`: 교수자 비밀번호
   - `GEMINI_API_KEY`: AI 해설용 키 (선택)
4. 배포 → 새 배포 → 웹 앱(실행: 나 / 액세스: 모든 사용자)으로 배포하고, 나온 주소를 `config.js`의 `SCRIPT_URL`에 넣습니다.
5. 교수자 화면은 주소 끝에 `?teacher=1`을 붙여 엽니다. PIN 조회에 성공해야 시험 중 정답이 보입니다.

## 문항 고치기
- 문항 원본은 `tools/pools_base.py`(기존 초안 문항)와 `tools/pools_new_L.py`, `tools/pools_new_R.py`(2026-11 추가 문항)입니다. 새 문항은 보기를 **정답이 첫 번째**가 되게 씁니다.
- 고친 뒤에는 차례로 실행합니다.
  ```
  python3 tools/build_sets.py               # data/lt1~8.js 다시 만들기
  node tools/check_sets.js                  # 형식·정답·세트 간 중복 검사
  node tools/export_lt_jobs.js > lt_jobs.json.new && mv lt_jobs.json.new lt_jobs.json
  python3 tools/make_audio.py lt_jobs.json audio   # 바뀐 듣기 음성만 다시 생성 (Kokoro 모델 필요)
  ```
- 세트 id(lt1~lt8)와 문항 번호는 운영 중에 바꾸지 마세요. 바꾸면 이전 기록과 연결이 끊깁니다.
